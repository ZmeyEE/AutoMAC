# 文件撰寫準則

這份準則記錄 README 與說明文件的寫法。依據是 2026-11-24 專案維護者親手改寫 README 後的版本：改寫後比原本的 AI 生成稿好讀得多。
以後新增或修改文件，先照這份寫，再用最後的檢查清單核對。

## 一、寫法

1. **照使用者的操作順序寫**：先寫要做什麼，再寫為什麼。章節依序是環境需求、快速開始、功能原理、角色、各端部署、安全、架構、測試、限制，用「1. 2. 3.」編號，讓人能用編號指路。
2. **句子短、直接**：一句只講一件事，不用口號、不用形容詞堆疊、不寫「強大」「完整」「簡單易用」這類沒有資訊的詞。能用表格就不用長段落（角色、通訊埠、顏色狀態、威脅與對策、設定檔位置）。
3. **註記集中，不散在每句後面**：驗證狀態、限制、尚未驗證的事項，一律集中寫在「已知限制與待驗證項目」。內文句子後面不掛括號註記。
4. **誠實寫沒驗證的事**：沒做過實機測試的，用「尚未完成實機驗證」明講；推算的數字要寫「由下載曲線推算」；使用者提供但沒有文件證實的規則，要寫「尚未經校方文件證實」。
5. **數字要有出處**：寫「實測」就必須有實測紀錄可查（日期、方法）；寫測試項數就用當下實際跑出來的數字。
6. **不重複**：同一件事只在一個地方詳細寫，其他地方一句話加「見第 N 節」。
7. **不放真實識別資訊**：MAC 用 `00-00-5E-00-53-xx`，IP 用 `192.0.2.0/24`，電腦名稱用 `LAB-SERVER` 這類通用名稱。見 `docs/隱私與安全檢查.md`。

## 二、指令與程式碼區塊

1. **語法要符合區塊標示的殼層**：標 `powershell` 的區塊就必須是 PowerShell 能執行的寫法。設定環境變數是 `$env:PYTHONPATH = "src"`，不是 cmd 的 `set PYTHONPATH=src`（在 PowerShell 裡 `set` 是 `Set-Variable` 的別名，不會設環境變數）。
2. **未簽章的 `.ps1` 要寫完整呼叫**：`powershell -ExecutionPolicy Bypass -File <腳本>`，因為 Windows 10 預設不允許執行未簽章腳本。
3. **打包後的 exe 沒有主控台**：`automac.exe` 的指令不會印出訊息，文件要說明「完成後會多出哪些檔案」，讓讀的人能確認成功。
4. **需要系統管理員或 sudo 的步驟要寫出來**：包含 Windows 的權限確認視窗、Linux 的 `sudo bash`。
5. **參數位置要寫對**：例如 `fix-nas-mount.sh --undo` 的 `--undo` 必須是第一個參數；寫文件時直接去看腳本怎麼解析參數。
6. **前置條件放在步驟前面**：安裝目錄、要先放哪些檔案、依賴 openssl 等，都要先於指令出現。

## 三、發布前檢查清單

- [ ] 文件裡的每個指令，都在乾淨環境或原始碼中確認過存在、參數順序正確。
- [ ] 區塊標示的殼層與語法一致（PowerShell 與 cmd、bash 不混用）。
- [ ] 數字（測試項數、耗時、CPU、記憶體）是最新的實測值。
- [ ] 時間參數的敘述與程式一致：例如「第二次確認至少間隔 5 秒、60 秒內沒確認就作廢」，不是「5 秒內確認」。去讀設定欄位的定義與判斷程式，不憑印象寫。
- [ ] 限制與待驗證項目完整，沒有只寫在別處的限制。
- [ ] 沒有真實 MAC、IP、電腦名稱、帳號、路徑、token；Word 的文件屬性與內嵌圖片也檢查過。
- [ ] 沒有引用公開庫裡不存在的檔案或工具。

## 四、這次改寫發現並修正的錯誤（供之後對照）

| 位置 | 原本的錯誤 | 正確內容 |
|---|---|---|
| 快速開始 | PowerShell 區塊用 `set PYTHONPATH=src` | `$env:PYTHONPATH = "src"` |
| 限速偵測 | 「第一次偏慢，5 秒內再確認」 | 至少間隔 5 秒後再確認；60 秒內沒確認則第一次結果作廢 |
| 用量帳本 | 統計值是「用量下限」 | 計數器含區網內部流量，會偏高；未跑 AutoMAC 的電腦不計入，會偏低；只是估計值 |
| 伺服器部署 | 沒有說明安裝目錄與前置步驟；用 `python -m automac hub init` | 先把 `automac.exe` 放進 `C:\AutoMAC`（或 `AUTOMAC_HOME`），用 `.\automac.exe hub init`，exe 不會印出訊息 |
| 伺服器部署 | 直接執行 `.ps1` | `powershell -ExecutionPolicy Bypass -File ...` |
| Linux 部署 | 缺 `sudo bash`、缺參數；還原寫成 `<名稱> --undo` | `sudo bash pi/fix-nas-mount.sh <名稱> [共用資料夾]`；還原是 `sudo bash pi/fix-nas-mount.sh --undo` |
| 環境需求 | 漏列 openssl | `hub init` 需要 Git for Windows 或其他 openssl |
