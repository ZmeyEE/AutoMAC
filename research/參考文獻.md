## 第三輪：實測（2026-11-23）
- python-zeroconf 0.154.0 已裝在 `.venv`（獨立環境，約 20 MB，不動系統 Python）。實測：本機通告加瀏覽成功，註冊約 1.7 秒（含名稱衝突探測）；通告者結束後（告別封包）6 秒內消失；可與 Windows 內建 mDNS 共存（5353 埠）；區網看得到另一台 Linux 主機與一台印表機的通告，代表多點傳送在這個網路是通的。尚未做兩台 Windows 機器互相看的測試。

## 第四輪：雙機實測（2026-11-23 晚）
- 本機（Win10）與伺服器（Win11）以 python-zeroconf 互相通告與發現成功，TXT 屬性（holder、ts）完整傳遞；註冊約 1.7 秒。
- **伺服器防火牆預設擋掉 python 的 mDNS 進站封包**（只有 svchost、瀏覽器有放行規則），沒加規則時雙方都看不到對方、伺服器連區網裡的印表機也收不到。已新增兩條規則（UDP 5353、限本機子網、對應 Python 3.12 與 venv 的 python.exe）後恢復。正式工具安裝時必須處理這一步。

GitHub：`plizonczyk/noiseprotocol`（225 星，MIT，2023 後未更新）與 `tgalal/dissononce`（59 星）實作 Noise Protocol Framework；**不採用**：需要新增相依套件、停更、沒有標準 TLS 的成熟工具鏈與審查量，且 Python 標準函式庫的 `ssl`（OpenSSL）已提供 TLS 1.3。mkcert 類專案是替本機開發產生受信任憑證，需要安裝本機根憑證，與「封閉群體＋釘選」的需求不符，不採用。

**決定**：標準函式庫 `ssl` 的 TLS 1.3（只允許 1.3）＋伺服器自簽 ECDSA P-384 憑證＋用戶端釘選憑證 SHA-256（握手後、送出任何資料前比對）＋TLS 內 256 位元 token＋失敗次數限制。憑證用 Git for Windows 內建的 openssl 產生（本機與伺服器都已有，不新增安裝）。
