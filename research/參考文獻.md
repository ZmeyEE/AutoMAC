## 第三輪：實測（2026-11-23）
- python-zeroconf 0.154.0 已裝在 `.venv`（獨立環境，約 20 MB，不動系統 Python）。實測：本機通告加瀏覽成功，註冊約 1.7 秒（含名稱衝突探測）；通告者結束後（告別封包）6 秒內消失；可與 Windows 內建 mDNS 共存（5353 埠）；區網看得到另一台 Linux 主機與一台印表機的通告，代表多點傳送在這個網路是通的。尚未做兩台 Windows 機器互相看的測試。

## 第四輪：雙機實測（2026-11-23 晚）
- 本機（Win10）與伺服器（Win11）以 python-zeroconf 互相通告與發現成功，TXT 屬性（holder、ts）完整傳遞；註冊約 1.7 秒。
- **伺服器防火牆預設擋掉 python 的 mDNS 進站封包**（只有 svchost、瀏覽器有放行規則），沒加規則時雙方都看不到對方、伺服器連區網裡的印表機也收不到。已新增兩條規則（UDP 5353、限本機子網、對應 Python 3.12 與 venv 的 python.exe）後恢復。正式工具安裝時必須處理這一步。

## 第六輪：Linux 組員端換 MAC 的做法（2026-11-24，使用者要求 Linux 客戶端）
查詢：網路搜尋與 GitHub。**ArchWiki 與 NetworkManager 文件讀了相關章節；其餘只看了搜尋結果的標題與摘要，未讀全文。**

| 項目 | 出處 | 與本專案的關係 | 採用？ |
|---|---|---|---|
| NetworkManager Reference Manual，802-3-ethernet 設定（`cloned-mac-address` 可填固定位址或特殊值 `preserve`、`permanent`、`random`、`stable`；讀了該屬性章節） | networkmanager.dev | 解釋 NetworkManager 重新連線時會不會蓋掉我們換的 MAC | **採用其結論寫進限制**：連線設了 `cloned-mac-address` 就會被蓋掉，需改 `preserve`；**不採用**改連線設定來換 MAC（會寫進設定、重開機仍保留，與「開機後再向伺服器要」的流程相反，也要依賴 NetworkManager） |
| Thomas Haller，clone-mac-address（NetworkManager 1.4 的 MAC 偽裝功能）（未讀全文） | blogs.gnome.org | 同上，說明 NetworkManager 自己提供的持久化做法 | 同上 |
| ArchWiki，MAC address spoofing（讀了全文） | wiki.archlinux.org | 手動有 iproute2（`ip link set dev X down`、`address`、`up`）與 macchanger 兩種；自動有 systemd.link、udev 規則、systemd 單元與 NetworkManager | **採用 `ip link set`**：只依賴 iproute2、不寫進設定、與發行版無關 |
| GNU macchanger（讀了 ArchWiki 對它的說明） | 發行版套件 | 可指定、隨機或依廠商改位址，是另一個要安裝的套件 | **不採用**：多一個外部相依，本專案只需要「設定成指定位址」 |
| 數個「用 Python 包 `ip link set`」的小型 GitHub 專案（如 MAC-ADDRESS-CHANGER-、basic_mac_changer） | GitHub | 流程與本專案相同：down、改位址、up、驗證 | **不採用**：沒有失敗還原、鄰居檢查與租約，只能參考流程；驗證一步由 `wait_ready` 取代 |

讀取側沒有找到更好的現成方案：`/sys/class/net`、`/proc/net/arp`、`/proc/net/route` 是核心提供的穩定介面，不需要解析指令輸出，也不需要額外套件。

**決定（真實測試後修正）**：裝置由 NetworkManager 管理且連線設了 `cloned-mac-address` 時，用 `ip link set` 換的 MAC 會在重新連線時被蓋回去（2026-11-24 在 netplan 設定的測試機上實測），所以這種情況改成暫時修改連線的 `cloned-mac-address`（`nmcli connection modify --temporary`）再重新啟用；其餘情況用 `ip link set` 的 down、address、up，再通知 systemd-networkd、dhcpcd 重新取址。讀取走 sysfs 與 procfs；服務用 systemd 單元。取捨與限制見 `nic.LinuxNic` 與 `svc_linux` 開頭的 shortcut 註解。
